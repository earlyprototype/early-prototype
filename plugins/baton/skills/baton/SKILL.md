# Baton

Produce a handover that lets the next agent continue this development session
without reconstructing the conversation. Invocation requests a snapshot of the
session; unfinished work must remain visibly unfinished.

Run only on an explicit invocation. Discussing Baton or saying "we're done" is
not an invocation. Any text accompanying the command narrows its scope or names
the destination; without arguments, cover the current development session.

The main agent owns the briefing and accuracy review. One subagent owns the
writing and follows the bundled [DrDoc skill](references/drdoc.md). This is a
coordinated workflow: the main agent must remain available for questions and
collect the result. Do not promise uninterrupted background execution.

## 1. Main agent: set the scope and destination

Read the project's applicable instructions and handover convention. Inspect the
current handover and the relevant working-tree state, where available. Keep the
inspection focused on this session; do not turn it into a documentation audit.

Use a user-specified destination when supplied. Otherwise, update an existing
document only if it is clearly the project's maintained current handover. Keep
historical handovers intact. If there is no maintained handover, follow the
project's naming convention or create
`docs/HANDOVER-YYYY-MM-DD-HHmmss-topic.md` using the actual current time. Check
for a collision and choose an unused suffix rather than overwrite another file.
Avoid files regenerated by existing hooks, including the timeteam
`session-handover-*.md` files. Never change or disable hooks as part of Baton.

Assign the subagent one exact output path. Honour existing document ownership
and review requirements; if the requested destination is locked, prepare a
separate proposed handover and flag the required owner decision.

## 2. Main agent: brief one writer

Use the host's native subagent facility. Explicitly pass the resolved absolute
path of `references/drdoc.md`, the output path, and these writer instructions.
The subagent must read DrDoc; merely naming the skill is insufficient. Do not
invoke another CLI or provider to simulate a subagent. If native delegation is
unavailable, explain that Baton cannot complete its delegated workflow here.

Give a compact briefing drawn from the session, even if history can be inherited:

- The user's objective, scope, constraints, accepted corrections and preferences.
- What changed, why, and which decisions the user actually made. Distinguish
  those decisions from agent proposals and unresolved questions.
- Relevant files, branch/worktree and uncommitted state, commands and observed
  check results. Say which checks were not run or no longer cover the current
  files. Identify unrelated work that must be preserved.
- Remaining work, blockers, known risks and the next useful action.
- The destination, intended reader, project conventions and evidence pointers.

Pass only context needed for the handover; do not dump a transcript or include
secrets. State what is unknown. Do not invent rationale to fill a gap.

Tell the writer: "You own only the assigned handover file. You are not alone in
the workspace. Preserve others' edits; do not revert them. Follow section 3
and read the supplied DrDoc file. Do not launch another handover agent. Return
the saved path, evidence checked, and any unresolved gaps to the main agent."

## 3. Subagent: verify, ask, and write

Read the complete supplied DrDoc skill and the relevant project instructions.
Apply DrDoc within the assigned handover scope. Report stale or conflicting
source documents to the main agent immediately; do not expand into repairing
other documentation or canonical specifications.

Check the briefing against actual files and available check results. Repository
evidence establishes what exists; the main agent supplies conversational context
and decision rationale. Neither substitutes for the other.

Ask the main agent for missing context when it would affect the handover's
accuracy or next steps. Use native messaging when available. If the host only
returns a final subagent result, return the focused questions so the main agent
can answer and resume you, or delegate the follow-up with your retained context.
Do not guess, ask the user directly, or wait indefinitely for an unavailable
channel. The main agent asks the user only when their answer is indispensable;
otherwise record the unresolved matter clearly.

Follow the project's document structure. Where none exists, use these sections
as needed, omitting empty ones:

- **Current state:** the objective, where the work stands and what the next
  agent needs to know first.
- **Changes and decisions:** relevant changes and their reasons; separate
  confirmed decisions from suggestions and open questions.
- **Evidence and checks:** concrete file/section links, commands and actual
  results, including failures, skipped checks and limits of verification.
- **Remaining work:** blockers and ordered next actions, starting with a
  concrete step; include any decision still needed from the user.
- **Working context:** necessary branch/worktree, uncommitted changes, setup
  and operational details. Preserve unrelated work.

Write for the successor. Lead with the point, use plain English, and cite stable
paths and section anchors. Capture decision rationale, not a chronological
account of the conversation. Make the document self-contained through concise
context and resolvable references. Label unsupported or unverified claims.

Save the handover and return its path, a brief account of evidence checked, and
any unresolved gaps. Do not call it reviewed or approved.

## 4. Main agent: review and present

Answer the writer's questions from the conversation and evidence. Read the
entire saved handover. Check accuracy, omitted context, decision ownership,
verification claims and whether the next action is usable. If relevant files
or decisions changed during drafting, give the writer that delta and review
the revision. Send corrections back to the writer until material gaps are
resolved or clearly recorded as unknowns or pending user decisions.

Present a link to the finished handover and any material unresolved point in a
short acknowledgment. If drafting or review failed, state what remains instead
of presenting an unreviewed document as finished.

Baton is complete when the handover is saved and the main agent has reviewed
it. This does not complete the underlying task, end the user's session, approve
work through a human gate, alter kanban state or session markers, or authorise
commits, pushes, merges or external syncs. Carry out those actions only when
separately authorised.
